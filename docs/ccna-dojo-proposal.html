> CCNA Dojo

A fast, offline Rust app for learning CCNA 1, 2 and 3 by doing. It ships with its own network simulator, labs that are graded on whether the network actually works, spaced-repetition drills, and an optional AI forge that drafts new exercises for you.

Core idea

Graded on what the network does, not on what you typed

Most practice tools compare your commands to an answer key, so a correct config written a different way gets marked wrong. The Dojo checks the result. Did the ping go through? Did R3 learn the route? Is the port trunking the right VLANs? That is how you get judged on a real job, and it means you can solve each lab your own way.

Answer-key grading

expect: "switchport mode trunk"
you:    "sw mo tr"           → wrong
you:    "switchport trunk allowed vlan 10,20"
        (before mode trunk)   → wrong order

State-based grading (the Dojo)

check ping   PC-SALES → 192.168.20.10   ok
check trunk  S1 Gi0/1 allowed = [10,20] ok
check route  R3 has O 192.168.10.0/24  ok
any config that produces this state passes

Packet-step mode is likely the most valuable feature. Pause any ping, then step it device by device. At each hop you see why it moved: ARP lookup, MAC table hit or flood, routing-table match, ACL line hit, NAT rewrite. Predict the next hop before you press Space and the app scores you.

CCNA 1 · Introduction to Networks

17 modules · L01–L06
L01

First contact

ITN 1–3 · Networking today · switch and end-device basics · protocols and models

Lab

Bring a factory-fresh switch onto the management network and lock the front door.

hostname S1
enable secret ********
service password-encryption
banner motd #Authorized access only#
interface vlan 1
 ip address 192.168.1.2 255.255.255.0
 no shutdown
ip default-gateway 192.168.1.1

Pass when PC1 pings 192.168.1.2 · running-config shows no plaintext passwords · config saved to NVRAM

L02

Bits on the wire

ITN 4–7 · Physical layer · number systems · data link · Ethernet switching

Drill

Convert 172.16.45.200 to binary and 0xC0A8 to decimal. Then: S1 receives a broadcast frame from AAAA.0001 on Fa0/1. Say exactly what it does.

Pass when 10101100.00010000.00101101.11001000 · 49320 · learn AAAA.0001 on Fa0/1, flood out every other port in that VLAN

L03

First hop

ITN 8–10 · Network layer · ARP · basic router configuration

Lab + packet-step

Address R1 for two LANs and route between them. Then step PC1's first ping hop by hop and predict who PC1 ARPs for.

interface g0/0/0
 ip address 192.168.10.1 255.255.255.0
 no shutdown
interface g0/0/1
 ip address 192.168.20.1 255.255.255.0
 no shutdown

Pass when PC1 reaches PC2 · first ARP request targets the gateway 192.168.10.1, not PC2

L04

Address math

ITN 11–13 · IPv4 and VLSM · IPv6 addressing · ICMP

Drill

Carve 192.168.50.0/24 for LANs of 60, 28 and 12 hosts plus one point-to-point link. Then compress 2001:0db8:0000:0000:0a00:0000:0000:0001.

Pass when .0/26 · .64/27 · .96/28 · .112/30 · 2001:db8::a00:0:0:1 (the leftmost of two equal zero runs gets the ::)

L05

Ports and conversations

ITN 14–15 · Transport layer · application layer

Drill

Client sends SYN seq=100. Server answers SYN-ACK seq=300. Fill in the server's ack and the client's final seq/ack. Then match DNS, DHCP, TFTP, NTP, SNMP and syslog to their ports.

Pass when ack=101 · seq=101 ack=301 · 53 · 67/68 · 69 · 123 · 161 · 514

L06

Small network, hardened

ITN 16–17 · Security fundamentals · build a small network

Lab

Replace Telnet with SSH on R1 and slow down password guessing.

ip domain-name dojo.lab
crypto key generate rsa modulus 2048
username admin secret ********
security passwords min-length 10
login block-for 120 attempts 3 within 60
line vty 0 4
 transport input ssh
 login local

Pass when Telnet to R1 is refused · SSH as admin succeeds · 3 bad logins trigger a 120 s block

CCNA 2 · Switching, Routing and Wireless Essentials

16 modules · L07–L11
L07

VLANs and inter-VLAN routing

SRWE 1–4 · Switch configuration · switching concepts · VLANs · inter-VLAN routing

Lab

Split Sales and Engineering into VLANs 10 and 20 and route between them on one trunk.

interface g0/0/1.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0
interface g0/0/1.20
 encapsulation dot1Q 20
 ip address 192.168.20.1 255.255.255.0

Pass when PC-SALES pings PC-ENG · S1 Gi0/1 trunks only VLANs 10 and 20

L08

Loops and bundles

SRWE 5–6 · STP concepts · EtherChannel

Predict + lab

Three switches in a triangle with equal-cost links. S1 and S2 run priority 32769 (S1 has the lower MAC) and S3 runs 24577. Name the root bridge and the blocked port. Then bundle S1–S2 Gi0/1-2 with LACP.

interface range g0/1 - 2
 channel-group 1 mode active

Pass when Root is S3 (lowest priority) · S2's port facing S1 is the alternate (blocked) port · Po1 shows (SU) with both members (P)

L09

Addresses on demand

SRWE 7–9 · DHCPv4 · SLAAC and DHCPv6 · FHRP concepts

Lab

Make R1 the DHCP server for its own LAN and for R2's LAN, which reaches it through a relay.

ip dhcp excluded-address 192.168.10.1 192.168.10.10
ip dhcp pool LAN10
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 192.168.30.53
! plus a second pool for R2's LAN
! on R2's LAN interface:
ip helper-address 10.1.1.1

Pass when First client lease is 192.168.10.11 · R2's clients get leases through the relay

L10

Edge security and wireless

SRWE 10–13 · LAN security · switch security · WLAN concepts and configuration

Troubleshoot

Break-it lab: PC3 lost connectivity after someone plugged a hub into Fa0/5. Find out why from show commands alone and recover the port.

Pass when Fa0/5 is err-disabled by port-security (max 2, sticky, violation shutdown) · fixed with shutdown / no shutdown after removing the hub

L11

The routing table

SRWE 14–16 · Routing concepts · static routing · troubleshooting static routes

Drill + troubleshoot

R1 has routes for 172.16.0.0/16, 172.16.5.0/24 and 172.16.5.64/26. Which one carries a packet to 172.16.5.70? Then fix a static route that points at the wrong next hop.

Pass when /26, because the longest prefix wins (it covers .64–.127) · the static route points at the neighbour's real next hop

CCNA 3 · Enterprise Networking, Security and Automation

14 modules · L12–L16
L12

OSPFv2

ENSA 1–2 · Single-area OSPFv2 concepts and configuration

Lab + predict

Run OSPF area 0 across three routers with passive LAN ports. Predict the DR on the shared segment, then force R1 to win it.

router ospf 10
 router-id 1.1.1.1
 network 10.0.0.0 0.0.0.255 area 0
 passive-interface g0/0/0
interface g0/0/1
 ip ospf priority 255

Pass when R3 shows R1's LAN as an O route · after clear ip ospf process, show ip ospf neighbor lists R1 as DR

L13

Threats and ACLs

ENSA 3–5 · Network security concepts · ACL concepts · IPv4 ACL configuration

Drill + lab

Write the wildcard for 172.16.32.0/20. Then allow only web traffic from VLAN 10 to the server at 192.168.30.10, placed as close to the source as possible.

ip access-list extended WEB-ONLY
 permit tcp 192.168.10.0 0.0.0.255 host 192.168.30.10 eq 80
 permit tcp 192.168.10.0 0.0.0.255 host 192.168.30.10 eq 443
 deny ip 192.168.10.0 0.0.0.255 host 192.168.30.10
 permit ip any any

Pass when 0.0.15.255 · HTTPS to the server passes, ping to it is dropped, other traffic is untouched

L14

Leaving the building

ENSA 6–8 · NAT for IPv4 · WAN concepts · VPN and IPsec concepts

Lab

PAT the whole inside network behind R1's outside interface, and publish the web server on a static public address.

interface g0/0/0
 ip nat inside
interface g0/0/1
 ip nat outside
access-list 1 permit 192.168.0.0 0.0.255.255
ip nat inside source list 1 interface g0/0/1 overload
ip nat inside source static 192.168.30.10 209.165.200.226

Pass when Inside hosts reach the ISP · show ip nat translations shows PAT entries and the static mapping

L15

Keep it running

ENSA 9–12 · QoS · network management · network design · troubleshooting

Troubleshoot capstone

Three faults are hidden in a 6-device network: a wrong access VLAN, an OSPF hello-timer mismatch and an ACL that drops DNS. Point NTP and syslog at the server first, then use the logs to find all three.

Pass when All three faults fixed · scored on time taken and on how few config lines you changed

L16

Networks as code

ENSA 13–14 · Network virtualization · network automation

Drill

The built-in mock REST API returns interface state as JSON. Find the interface that is down, then write the JSON body that sets its description.

GET /restconf/data/ietf-interfaces:interfaces

Pass when Correct interface named from the JSON · valid PATCH body accepted by the mock API

AI forge

Unlimited practice, checked by the simulator

The forge drafts new exercises for any level. It works with any provider you link, or with no provider at all. The safeguard is that AI output is never trusted blindly: every generated lab must include a reference solution, and the Dojo runs that solution in the simulator. If any check fails, the lab is rejected before you ever see it.

Focused mode

Only the current level's topics. Use it to drill a new skill until it sticks.

Cumulative mode

The current level plus everything before it, weighted toward the weak spots your review history shows. Use it to stop old skills from fading.

  1. ContextLevel topics, mode, your weak spots, the lab schema
  2. DraftSent to your provider, or copied as a prompt you paste anywhere
  3. ParseTOML is validated against the schema
  4. ProveThe reference solution runs in netsim and every check must pass
  5. QueueSaved to your content library and scheduled

Content format

Labs are plain files you can read and edit

Everything lives in content/ as Markdown and TOML. Each item is tagged with its Networking Academy module and its exam objective, so the same lab appears in your course view and your exam view.

[lab]
id      = "srwe-l07-router-on-a-stick"
level   = 7
academy = ["SRWE-3", "SRWE-4"]
exam    = ["v1.1:2.1", "v1.1:2.2"]

[topology]
devices = ["R1:isr4321", "S1:c2960", "PC-SALES:host", "PC-ENG:host"]
links   = ["PC-SALES:eth0 -- S1:Fa0/5", "PC-ENG:eth0 -- S1:Fa0/6", "S1:Gi0/1 -- R1:G0/0/1"]

[[check]]
desc = "PC-SALES reaches PC-ENG"
ping = { from = "PC-SALES", to = "192.168.20.10" }

[[check]]
desc  = "S1 Gi0/1 trunks only VLANs 10 and 20"
trunk = { device = "S1", port = "Gi0/1", allowed = [10, 20] }

[[fault]]   # optional: break-it variant
device = "S1"
inject = "interface fa0/6\n switchport access vlan 30"

Build order

P6Beyond

OSPFv3, multi-area OSPF, EIGRP, eBGP basics, and the real-lab bridge that exports labs to containerlab or GNS3 and checks real IOS over SSH.
