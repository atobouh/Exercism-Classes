Everything so far in this chapter exists because IPv4 ran short of addresses. IPv6 was designed so that the shortage cannot happen again, which changes what NAT is for. This page covers what IPv6 does about private addressing, and the one kind of translation that remains useful: helping IPv6-only hosts reach IPv4-only services during the long move from one protocol to the other.

## IPv6 does not need NAT to save addresses

An IPv6 address is 128 bits, which allows about 3.4 x 10^38 addresses. A site typically receives a /48 or /56 prefix from its provider. A /48 holds 65,536 subnets of /64 size and even a /56 holds 256, so every device can have a globally unique address. With no shortage, there is no reason to hide forty PCs behind one address, and every benefit of end-to-end addressing that NAT took away is back: a host's address is its own, and any host can in principle reach any other.

Reaching a host is a routing matter, and whether it is allowed is a firewall matter. As you saw on the [cost of NAT](ensa/06/04-nat-tradeoffs) page, NAT was never a firewall. An IPv6 network gets its protection from the same ACLs and stateful firewalls that protect IPv4.

## Unique local addresses

IPv6 does have an equivalent of private addressing. *Unique local addresses* (ULAs) come from fc00::/7, and in practice sites use fd00::/8, filling in a random 40-bit global ID to form a /48 such as fd12:3456:789a::/48. The random part makes two sites very unlikely to pick the same prefix, which is the problem that RFC 1918 reuse caused in IPv4.

ULAs are not routed on the internet, and they are used for traffic that should stay inside the organization. But they are not meant to be translated. A host that needs internet access also gets a global unicast address from the 2000::/3 range, and it uses that address for the outside world. Many IPv6 hosts hold both at the same time.


## Moving from IPv4 to IPv6

The two protocols cannot talk to each other directly. An IPv6 host cannot send a packet to an IPv4 address, and the other way round. Because the world cannot switch on a single day, three kinds of transition method are used while both exist.

| Method | Idea | What each device needs |
| --- | --- | --- |
| Dual stack | Run IPv4 and IPv6 side by side on the same devices | Both protocols configured |
| Tunneling | Carry IPv6 packets inside IPv4 packets across an IPv4-only part of the path | A tunnel endpoint at each end |
| Translation | Convert packets between IPv6 and IPv4 as they cross a boundary | A translator in the middle |

*Dual stack* is the preferred method wherever it is possible, because each conversation uses whichever protocol both ends support, and nothing is translated. Tunneling is a way to cross an obstacle, not a way to talk to IPv4 hosts. *Translation* is the one that connects the two worlds.

## NAT64

Suppose a network has been built IPv6-only, which saves running two protocols and needs no private IPv4 space, but a few of the servers its users need are still IPv4-only. *NAT64* sits at the edge and does for protocol versions what ordinary NAT does for addresses.

The host asks a DNS64 server for the name of the web site. Since the site has no IPv6 address, DNS64 builds one by embedding the IPv4 address in an IPv6 prefix reserved for translation (the well-known one is 64:ff9b::/96). The host sends an IPv6 packet to that address. The NAT64 device recognizes the prefix, rewrites the IPv6 header as an IPv4 header, uses its own IPv4 address as the source, and keeps a table so that it can translate the reply back, just as in PAT.

NAT64 is stateful, in the same way as PAT. It is a transition tool, not a design to build around: it helps IPv6-only networks live a little longer alongside the IPv4 internet, and it goes away when the last IPv4-only server does. The older method, *NAT-PT*, did a similar job but was found to have too many problems, and it is deprecated.

```question
prompt = "Which transition method keeps both IPv4 and IPv6 running on every device, with no translation?"
options = ["Tunneling", "NAT64", "Dual stack", "NAT-PT"]
answer = 2
why = "In dual stack each host and router runs both protocols and uses whichever one the other end supports. Tunneling wraps one protocol inside the other, and NAT64 and NAT-PT translate between them."
```
